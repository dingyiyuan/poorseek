## 三、今天的核心发现：**CED/YOCO 早就实现了**

### 3.1 三个框架的交叉验证
- **DeepInfer（官方的最终解释）**：机制叫 **YOCO prefill truncation**，
  `DEEPINFER_YOCO_PREFILL_TRUNCATION_MODE ∈ {off, mask, compact}`，`KEEP_TOKENS >= window + backtracking`；
  注释写死 **"decode 恒走 full 布局，传 off"** —— 官方就是这样防止解码减层的。
  配置映射 `layer_kv_map = _source_map(kv_source_layer_ids)`（每层取"不晚于它的最近源层"）。
- **vLLM** `models/deepseek_v41/decoder_replay_layers.py`：源层先给**所有行**写 KV，后续层只跑
  **最后 `window` 行**，**"被裁掉的行输出留零，没人读"**。
- **SGLang** `models/deepseek_v4_replay_tail.py`：`layer_ids=range(late_layer_start, end)`、`row_step=SWA_WINDOW=128`。

### 3.2 我们的引擎早就有
- `ds4.txt` 元数据齐全：`sliding_window 128`、`kv_source_layer_ids 2,8,14,20`、
  `index_source_layer_ids 2,8,14,20,24,28,32,36`、`candidate_source_layer_id 20`。
- `Layer` 结构有 `kv_src/ix_src/cand_src/ik_src`（对应 vLLM 的 `_source_map`）。
- **chunk 路径已实现 YOCO**：`yoco_layer()` + `DS4_YOCO_KEEP`（默认 keep = `(nl-yl)*(win-1)+win` = **316 行**），
  只在 `n - keep >= kYocoMin(1024)` 时启用。
- 代码注释直接引用："DeepSeek's own serving replays the last 128 tokens through those layers (DeepInfer's SWA bounded replay)"。

**→ 结论：没有 2× 的 CED 空间可捡。** 我们已经在做 CED，只是 keep=316 行（官方是 128+backtracking）。
