# 宣传文案（2026-11-03）

## 中文短版（论坛/群，可直接发）

**单张 Intel Arc Pro B70，q2 权重的 DeepSeek-V4.1-Flash，62k 提示预填充 375 → 944 tok/s（2.5×），解码不掉。**

原因不神秘：MoE 专家内核按「64 行一块」切分激活，而每一块都会把**同一份专家权重重新解量化一遍**。
900 行/专家的提示就要解 **15 遍**。改成每个专家只解一次到 f16、再走一次 f16 GEMM（XMX），就完事了。

拆开看这 14.5×：**6.95× 是那 14 遍重复解量化消失**，**2.09× 是内积从 F32 搬到张量核**。
（把解量化在同一个内核里重复 N 遍测出来的，线性到 1,704 µs/遍，所以不是估算。）

- 解码不变：阈值 96 行，单 token 仍走融合内核，稳态 20.8–20.9 tok/s
- 数值更好（内核级对拍 7 种量化类型全过，最差 3.61e-04 / 容差 1e-02）：gate/up 3.34e-04（原来 7.02e-03），f16 权重 + f32 累加比逐值 f32 更准
- 这也解释了为什么"越长的提示越亏"：重复次数就是 `ceil(rows/64)`

上游 Strata 的 CUDA 版有完全一样的 grid（`src/dsv41/ds4_iq.cu:1595`），已提报告：
https://github.com/Niko1221/Strata/pull/5047

复现：`DS4_EXP_2PHASE=1 ./build-sycl-tc2/ds4_iq_test_tc --bench-tiles 16 6 900`

## English short (for GitHub / Reddit / X)

**One Intel Arc Pro B70, DeepSeek-V4.1-Flash with q2 (IQ2_XXS) experts: prefill 375.8 → 944.1 tok/s
(2.51×) on a 62K prompt. Decode unchanged.**

The MoE expert kernel tiles the prompt by 64 activation rows, and every tile dequantizes the *same*
expert weights again - 15 redundant passes at 900 rows/expert. Dequantize once per expert into f16,
then one f16 GEMM per matrix on the tensor cores.

Where the 14.5× comes from (measured by repeating just the dequantize N times, linear at 1,704 µs/pass):
**6.95× the redundancy going away, 2.09× the inner product moving to XMX**. Decode keeps the fused
kernel (96-row threshold) and holds its 20.8-20.9 tok/s. Numerics slightly *improve*.

The same grid exists upstream (`src/dsv41/ds4_iq.cu:1595`) - reported with measurements as
Niko1221/Strata#5047.

## 一句话结构（发帖开头用）

> 一个「每 64 行就重新解量化一遍同一份权重」的设计，在长提示下把专家内核拖到 5 TFLOPS；
> 让它每份权重只解一次，配合张量核 f16 GEMM，预填充直接 2.5 倍。

## 别说的（避免被打脸）

- 不要说“输出逐字一致”——这个引擎的采样本身就不逐位确定（同配置两次 117/114 token），端到端只能比内容对不对，不能比字节。

- 不要说"预填充已经优化完"——剩下还有一项：那唯一一遍解量化占两段式时间的 42%，且要写 f16 scratch。
- 不要说"解码也变快了"——解码没动，20.8–20.9 tok/s 是原来就有的。
- 不要拿 8–24 token 的窗口报解码速度（我就踩过，报成 9.3，实际 20.9）。
