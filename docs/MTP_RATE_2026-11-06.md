# MTP 没丢：它一直是 `--dspark off`（2026-11-06）

## 1. 先回答：「15-16 tok/s」和「34+」量的不是同一件事

昨夜那批数字（24×128 → 中位 14.9；60 请求浸泡 → 中位 15.2）是 **`--dspark off`** 跑的。
理由写在 `tools/dsv41/slow/repro.py` 里：它把生产配置的 `--dspark` 换成 `R3_DSPARK` 环境变量，
默认 `on`，而我三次都显式传了 `R3_DSPARK=off`——为了做**背压修复的 A/B**（变量只留 `DS4_LANE_BP` 一个）。
所以那 15–16 从头到尾都是**纯单 token 解码**的速率，跟 MTP 有没有退化无关。

另外，生产配置本身也是 off：

```
--pack /data/models/dsv41-iq2xxs-pack-real --max-context 393216 --gpus 0 --experts 6
--threads on --prefill-chunk 40960 --mmap-experts auto --vram-experts 1.0 --ssd-cache 0
--dspark off --vision off --window 16
```

`:8160` 上跑的 `dsv41.service` 用的就是这份，所以你在 API 上看到的 15–16 tok/s 是**必然的**。

## 2. 34.30 tok/s 是什么条件下的数

`docs/MTP_HANDOVER_2026-11-04.md` §312-315 的原始记录：

| 配置 | 速率 |
|---|---|
| `--dspark off` | 15.16 tok/s |
| `--dspark on` | **34.30 tok/s**（+83%） |

同一张表下面还有一句：**「两边的输出都会退化成复读」**——那是配置文件里的一条偏置 prompt
（可复读流）跑出来的，MTP 在这种流上接受率接近 100%，是最理想的情况。
`docs/DECODE_PCIE_PLACEMENT_2026-11-03.md:406` 里同样配置在真实文本上只有 **18.18–18.74**。

所以「34+」= **MTP on + 可预测流**；「15-16」= **MTP off + 真实文本**。两个都没错，只是不同坐标系。

## 3. 留档的新数据：MTP on 在真实问题流上的样子

为免下次再对不上，今晚补跑了 12 请求 × 512 token、**MTP on**、`--vram-experts 1.0`、
真实问题（同 `repro.py` 的四问轮转）、`R3_TIMEOUT=240`：

| 指标 | MTP **on**（本轮） | MTP off（昨夜，同夹具） |
|---|---|---|
| 中位速率 | **19.58 tok/s** | 17.09 tok/s |
| 均值 | 23.56 | 17.34 |
| 范围 | 14.75 – **45.05** | 13.15 – 24.59 |
| `down+post` | 2.0–2.4 ms/层 | 0.14–0.19 ms/层 |
| swaps/请求 | 98–952 | **0** |
| 生成长度 | 22–512（平均 ~216） | 30–260 |

逐条：

```
#1  239 tok  20.6   #5  239 tok  39.2   #9   239 tok 19.4
#2   22 tok  14.8   #6  512 tok  16.1   #10  239 tok 17.4
#3   78 tok  16.2   #7  239 tok  19.8   #11  239 tok 27.3
#4   93 tok  16.8   #8  239 tok  45.0   #12  239 tok 30.1
```

**怎么读**：
- 真实文本上 MTP 的收益是**离散的两档**：能凑出高接受率的请求冲到 **39–45 tok/s**，
  不能的（答案短、或模型在自由生成）落回 **15–20**。中位只比 off 高 ~15%，
  但**上档远在 34+ 之上**——你说的「带 MTP 34+」是能复现的，只是它属于那一档的自动写作/长回答。
- 生成长度是这道题的一部分：22–93 token 的短答没有摊薄空间（每轮 verify 的开销固定）。
- `down+post` 从 0.14 涨到 2.0+ ms/层，是 MTP 每轮多验 3–5 个 token 的正常代价
  （handover §10：T=6 时 5.75 token/轮，verify 128.6 ms/轮）。
- swaps 每请求 98–952：MTP 每轮验多个 token，碰到的专家更多，专家环换入换出随之增加。
  这**不是**泄漏——60 请求 off 那轮 swaps 一直是 0，说明平时环根本不换。

## 4. 要长期开 MTP 的话，动这一个参数就够

生产 `strata-server.json` 里 `--dspark off` → `on`，然后
`systemctl --user restart dsv41.service`。前提与代价：

1. **显存**：`--vram-experts 1.0` 只剩 ~595 MiB，而 MTP 的 drafter 还要 ~7 GB
   （handover §8 与 §180）。要开 MTP，先把 `--vram-experts` 降到 **0.5 或 0.75**
   （0.5 是历史上「全程不掉崖」的安全档，代价是速度降到 ~28 tok/s 那档）。
2. **输出不再逐次可复现**：MTP 路径两次跑同一 prompt 的输出可能不同
   （`MTP_HANDOVER` §11.2），正确性口径只能用**统计**（24 题准确率），不能用 md5。
   24 题那轮 24/24 是 off 跑出来的，开 MTP 后要**重跑一次**才有 OE 结论。
3. **长短请求体验差异大**：短答 15–20、长答/可预测流 39–45，中位 ~19.6。
   如果你的 agent 会话以长回答为主，收益会比这批真实短问明显。

## Paired A/B re-measurement (2026-11-07 07:15-07:30)

The figures above come from different sessions with no paired control. This run fixes that:
same binary (`ce04904`), same pack (`-mtp2`), same prompt ids, `--vram-experts 0.5`,
256 tokens, arms **interleaved** in one process loop after two warmups, three pairs.

| arm | run 1 | run 2 | run 3 | median |
|---|---:|---:|---:|---:|
| `--dspark none` | 27.54 | 27.71 | 27.72 | **27.71** |
| `--dspark on` | 35.88 | 36.38 | 35.86 | **35.88** |

**+29.5% from MTP** (35.88 / 27.71 = 1.295). Within-arm spread is under 1.5% on both sides
(27.54-27.72 and 35.86-36.38), so the separation is far outside the noise.

This is lower than the earlier standalone figures (43.9 / 26.0, i.e. +69%). Those were 512 tokens
on a different pack/settings. On this prompt and this config the honest number is **+29.5%**.

### Why the first attempt produced empty rows, and what it cost

The first pass used a 400 s timeout per run. Loading this pack takes longer than that on a cold
page cache: the log shows 189 GB of read-ahead and 127 GB copied into the lane, so ON#1 and OFF#2
were killed mid-load. That is a **timeout, not a crash and not a slowdown** - the rerun with a
1200 s timeout produced all six rows. Any harness on this pack needs the timeout at >= 1200 s.

### Not measured here

Correctness under MTP is not established by this run. The earlier statistical check (18/24 vs the
19/24 and 24/24 history) was on `pack-real` with `--dspark none`; MTP requires the `-mtp2` pack,
and the engine's output is not reproducible run to run with drafting on, so only a statistical
comparison would mean anything. That has not been run on this pack.
